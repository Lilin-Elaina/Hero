# 2026-11-12 CAN2 全瘫排查（只有 pitch 能遥控）

## 现象
遥控器只能控 pitch（CAN1）；底盘四轮+yaw（CAN2）全死。Ozone: RC_WheelFault=15(四轮全标故障),
dj_wheel[0..3].last_tick 冻结, can_rx_205=0, can_rx_last_id 只见 514/515/518(全 CAN1)。

## J-Link 寄存器实证（无暂停只读）
- FDCAN2 CCCR=0x1000 → INIT=0 外设正常运行（★排除 bus-off 卡死/未启动）
- FDCAN2 PSR=0x77B → EP=1(错误被动) LEC=3(ACK错误)；ECR TEC=128 封顶、REC=0
- TXFQS bit21=1 → 发送队列满：0x200/0x1FF 指令在排队，无人接收
- GPIOB MODER/AFR0: PB5/PB6 = AF9 ✓ 引脚配置完好
- GPIOB IDR 连续采样 0x2010↔0x2070 → PB5/PB6 在翻转 = 控制器在持续重发，
  收发器逻辑侧活着（RXD 跟随 TXD），且总线侧驱动级也在驱动（RX 能看到显性）
- FDCAN1 一切正常（LEC=0）

## 结论：纯硬件问题，软件 100% 干净
签名 = "MCU 持续发送 CAN2 帧，但**总线上没有任何节点应答**"（ACK 错误封顶+零接收）。
断点在 CAN2 收发器总线侧→五个节点（4×C620+yaw 6020）之间：
线束/插头断开、或五个节点集体失电（公共电源轨）。
★ 排除记录里两个旧嫌疑：① PC0/PC3(ins_gpio_init) 与 CAN2 无任何硬件/代码关联，
  且 ins_gpio_init 已注释的当前固件故障依旧；② 不是 bus-off 恢复卡死（CCCR.INIT=0）。

## 硬件排查顺序（交用户）
1. 重新插拔 CAN2 座插头（用户刚在板子上戳过，最大嫌疑）
2. 看 4 个 C620 + yaw 6020 的电源 LED —— 全灭=电源轨断，全亮=线束断
3. 断电测 CAN2 座 CAN_H~CAN_L 电阻：~60Ω=正常(两端120R)，120Ω=末端节点脱开，∞=干线断
4. 上电测 CAN_H/CAN_L 对地电压：应 ~2.5V；沿线逐点测找到断点
5. 都正常则 CAN2 收发器总线侧损坏（戳板时 ESD/短路）

## 背景
- 本轮新增代码只有 BMI088/SPI2（main.c/spi.c/ins.c/gpio.c 加 PD2），git diff 证实
  fdcan.c/rc_dbus.c/mecanum.c/bsp.can.c 一行未动。
- SPI2=PC1/PC2/PB13，与 FDCAN2(PB5/PB6) 无冲突。
- pitch 使能是硬编码 1u（rc_dbus.c:638），不受右拨杆门控 → "只有 pitch 能动"不等于其他链路是软件问题。
