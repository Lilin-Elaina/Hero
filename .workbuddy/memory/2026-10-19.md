## 6020 不转的直接原因（已核实）

  `DJ6020_Send_I` 永远发 0。这是设计好的"量角度模式"，不是 bug。
- 接收链路已逐项核对全通：Filter 全收→FIFO0、ActivateNotification(bsp.can.c:34)、
  NVIC FDCAN2_IT0(fdcan.c:122-123)、FDCAN2_IT0_IRQHandler(it.c:222)、回调解析大端正确。
- 通道映射正确：RC_CH_GIMBAL = ch[0] = 右摇杆水平（官方解码），无需改 ch[1]。

  指示灯"橙灯常亮"= 电流控制模式下接收到电压指令。电流模式须改发 0x1FE 帧(±16384↔±3A)。

## JLink 实测(23:13, 帮用户测限位时发现总线瘫了)
- 工具: D:/jlink/JLink_V984/JLink.exe, -device CORTEX-M7 (JLink 不认 STM32H723 名字), SWD, CommanderScript 读内存, 不 halt 不影响固件运行。
- gim6020 @ 0x200001EC, RC_Data @ 0x20000210 (last_tick @ 0x20000238), FDCAN2 base=0x4000A400 (D2_APB1+0xA400, 已从 stm32h723xx.h 核实; RXF0S@0xA4, PSR@0x44, ECR@0x40, CCCR@0x18)。
- 实测证据(23:13, 6020 已接上电):
  1. RC_Data.last_tick 0x000C214C→0x000C2E0A 正常增长 → 固件在跑、DBUS 在收、遥控在线 ✓
  2. gim6020 三字全 0, last_tick=0 → 0x205 反馈从未进过程序
  3. RXF0S=0 (F0FL=0, F0PI 恒 0) → RX FIFO 从未收到任何帧(连 C620 的 0x201/0x204 都没有!)
  4. ECR: TEC=184→0 (爬到 bus-off 被 bsp.can.c 的 BUS_OFF 回调 Stop+Start 清零, 循环往复), REC 11→66 在涨
  5. PSR: EP=1(错误被动), EW=1, LEC=5(bit0 error) → 物理层位错误
- 结论: 总线上所有节点(含 C620)都无应答、无任何帧进来 → 总线物理层瘫, 非 6020 ID 问题(ID 错不影响 ACK)。用户接 6020 之前 3508 能动 → 接入 6020 这一下搞瘫总线。
- 头号嫌疑: 6020 拨码第4位终端电阻 ON(与原有 2 个 120Ω 并联=40Ω 拖垮幅度); 次嫌: CAN_H/L 接错/没并上、共地、6020 CAN 未真正接入 FDCAN2 总线。
- 用户检查硬件后, 用同一套 JLink 脚本复测: 看 F0PI 开始增长 + TEC 稳定为 0 + gim6020.angle 开始变 → 总线活了, 然后继续量限位(手转云台采样 min/max)。

## 【重要更正】23:13 的 ECR/PSR 标签弄反了, 重新解读
- 当时脚本读 0x440 和 0x444, 但我在分析里标反了: 0x440=ECR, 0x444=PSR (CMSIS 头文件已复核: ECR@0x40, PSR@0x44, CCCR@0x18)。
- 修正后 23:13 真相: ECR(0x440)=0x00FF7100 → **TEC=0(我们发的帧有人 ACK, 发送链路其实是通的!)**, REC=113→119,
  CEL=127 饱和 → 接收几乎全是误码(几千帧里只偶尔解码出个位数), RXF0S put index 恒 0 是"收到帧全坏、没一帧合格入 FIFO"。
- 即故障模式是"发得出、收不进"= 单边物理层损伤的典型特征(一根线接触不良/接错), 不是"全网无应答"。
- 日志原第 4/5 条(TEC=184→0、EP/LEC 描述)实为 PSR/ECR 颠倒的误读, 以本条为准。

## 【教训】JLink 脚本绝不能带 r/h 命令读运行中的固件
- read_v2/read_angle.jlink 开头写了 `r`(复位)+`h`(暂停) → 每次采样把板子复位一次, 读到复位后未初始化乱数据
  (23:28-29 的"角度乱跳/last_tick 卡 1000"全是这个假象)。arm-none-eabi-nm 复核 elf 未重烧(22:47)、地址未变。
- 正确脚本 read_live.jlink: 只有 mem32+qc, 无 r 无 h。验证: gim6020.last_tick 5s 增长 4544ms, 数据物理合理。
- 顺带: RC_Data.last_tick=0 → 采样期间 DT7 遥控器没开。
