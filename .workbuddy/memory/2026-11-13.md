## 两个症状的架构级诊断(用户带来的分析, 我已核实, 结论成立)
1. 推yaw云台+底盘摆动: 根因=推杆/松杆两套目标(rc_dbus.c:544 双分支) +
   航向保持把修正速率积分进"编码器位置目标"(内环 ANG_KP=0.22rpm/count 极软,
   追 400°/s 修正需 303counts=13° 滞后) + 跟随 KICK 继电器 → 三层软环互搏。
   正解=统一世界系链: 摇杆→ψ_ref(推杆更新/松杆冻结)→世界角P→速率目标→
   陀螺速率PI(速度反馈从编码器rpm换成陀螺deg/s)。编码器只留 α/跟随/超时。
2. 小陀螺前进不沿枪口: 三个实锤(数值核实)——
   a) 逐轮±1截断(mecanum.c:114): 满杆fwd+基础自转0.27时 LF/LB=0.73, RF/RB=1.27→被截1.0, 比例破坏;
   b) 0.85横移权重在换系后乘 → 斜向指令方向偏 ~5°(静态正交角测试暴露不出);
   c) 斜坡在车体系里: 手持杆不动时车体系四轮目标仍以 ω≈2.3rad/s 旋转,
     A·ω>1.5/s(加速度限幅)即整矢量滞后; 结构性修法=斜坡/手感权重全部挪到
     换系之前的枪口系(枪口系里"手持杆"=常值目标, 斜坡自然收敛, 不再对抗)。
   修后残余: 车体系轮速参考仍在旋转, 由轮速PI(带宽远高于斜坡)跟踪, 量滞后用
     RC_WheelRef vs dj_wheel[i].rpm 相位差实测。
- 推荐流水线: 枪口系(死区/权重/斜坡) → 坐标变换 → 麦轮逆解 → 整体等比缩放 → 轮速PI。

## 参考工程 RM_hero_ctype(2024英雄, D:/BaiduNetdiskDownload) 佐证(23:11 读毕)
- **小陀螺稳向 = 底盘角速度直接前馈进 yaw 速度环参考**: gimbal.c:52
  `.speed_feedforward_ptr = &chassis_fetch_data.real_wz`; dji_motor.c:274
  `pid_ref += *speed_feedforward_ptr`。real_wz=指令 wz/1000(chassis.c:364,
  EstimateSpeed()是空壳→他们用的是"指令值"非"测量值", 零噪声零滞后)。
- **yaw 闭环全在 IMU 世界系**: 角度环用 YawTotalAngle(多圈连续), 速度环用 Gyro[2],
  编码器只用于算 offset_angle(跟随/换系)。速度PID: Kp=100 Ki=200 Kd=70,
  **IntegralLimit=3000 vs MaxOut=30000 → 积分权限仅 10%**(前馈扛主干, 积分只补残差)。
- **跟随模式防摆机制(治"推yaw云台底盘一起摆")**: chassis.c:292
  `wz = PID(offset_angle,0) − 1.02*REAL_WZ_RAT*Gyro[2]` —— 把云台实际世界角速度
  **1:1 前馈直通进底盘 wz 指令**, 底盘跟着云台转, 跟随 PID 只修残余 offset。
  (与"底盘转速→云台前馈"互为镜像, 两环解耦)。这是用户跟随摆动问题的
  参考级正解, 属跟随模式改动, 用户本轮明确不动跟随, 留作下一步。
- **底盘运动学流水线**(治"小陀螺前进不沿枪口"): vx/vy 先成形(枪口系) →
  按 offset_angle 旋进车体系(chassis.c:346-347) → 麦轮解算 → **直接设速度环
  参考, 车体系无逐轮斜坡**(LimitChassisOutput→DJIMotorSetRef)。印证此前
  "枪口系成形→换系→逆解→轮速PI, 斜坡别放在车体系"的结论。
- **小陀螺转速不是恒值**: 正弦变速(随机0.3~1Hz, ±1000绕6000基准, 超电门控),
  反预测设计; 用户恒速+trim 可后仿。
- 差异决策: 用户用"测量值"前馈(ω_c=wz_ms−6·rpm, τ50ms LPF)而非参考工程的
  "指令值"——因为用户 spin 指令拨杆瞬间跳满值而底盘要斜坡起转, 指令前馈会
  在起转瞬间过补(枪口反向甩), 测量前馈自然跟随底盘实际起转曲线。
