# 2026-11-07 架空偶发单轮失控诊断（只读排查，未改代码）

## 现象
- 架空时某个轮子突然无法遥控（推杆不响应），其余轮正常。
- 回中摇杆后，不转的轮会反复短暂转动，最终停下。

## 代码彻查结论
- 四轮电流在 RC_Control_Task 同一循环算出、装进**同一帧 0x200**（DJ3508_Send_I_Can2）。
  ⇒ 软件不存在"只杀一个轮"的路径：三个轮听指挥 = 0x200 帧在总线上且被正常执行，
  死轮是该 C620 自己在"装死"（不执行/离线），矛头指向电调侧或 ID 冲突。
- 唯二的单轮软件状态逐一排除：
  1) s_wheel_i[k] 卡住: ref=0 且 rpm=0 时 err=0 → 冻结不动，只会造成"单次转一段后停"，不会反复。
  2) dj_wheel[k] 反馈丢失: 走 FAULT_ISOLATE=0 → **整车**断电，不是单轮。
- 接收回调总线分流正确（hfdcan->Instance==FDCAN2 ? dj_wheel : dj_motor），CAN1 摩擦轮
  0x202/0x203 不会污染 dj_wheel。bus-off 恢复(bsp.can.c)是修过的正确版本。
- 回中"反复抽动"机制 = 松杆 250ms 斜坡(ref 非零衰减) × 故障门反复开关(该 ESC 反馈间歇丢)，
  每次故障恢复都拿衰减中的 ref 重新驱动一轮 → 抽动到 out[] 归零为止。ST_STOP 状态机
  (11-06 方案)未实施前这是预期行为。

## 硬件嫌疑排序
1. ★C620 拨码 ID 重复（两个电调同 ID）：两 ESC 同时发同一反馈 ID → 总线冲突 → 一方
   bus-off(轮死) → 自动恢复 → 再冲突 → 周期性离线/在线 = 单轮死 + 回中反复抽动，
   一套理论同时解释两个现象。
2. 该电调供电/接插件虚接 → 欠压复位循环。
3. 该轮 CAN 支路(T头/串联线)接触不良。
4. C620 本体故障（LED 可判）。
5. CAN2 总线负载偏高：4 轮反馈 4k + yaw 0x205 1k + 0x200/0x1FF 各 1k = 7k 帧/s ≈ 77%，
   余量小，任何错误帧/重传都会拥塞。CAN1 约 55% 正常。

## 判别手段（不改代码）
- 二分法: 死轮时推杆看另外三轮。三轮动→电调侧; 四轮全死→总线/MCU bus-off/DBUS。
- 目检: 四个 CAN2 C620 拨码是否 1/2/3/4 各一个; 死轮时该电调 LED 颜色/闪烁。
- J-Link 只读: dj_wheel[0..3].last_tick(哪个冻结)、can_rx_total(健康≈8000/s 涨)、
  RC_WheelFault(0/1 跳变?)、FDCAN2 PSR(0x4000A444)/ECR(0x4000A440)。
- 拔插该电调 CAN/电源看是否复活; 与好轮对调电调看问题是否跟随。
- 注意: 10-25 曾观测 CAN2 ID2(0x202) 无反馈——确认死轮是否固定是 ID2/右前。

## 软件可加固项（确认根因后再做，现在不动）
- DJ3508_Send_I_Can2 返回值未检查: bus-off 期间 TX 静默丢帧，无法观测。
- 可加每轮反馈帧计数器 + TX 失败计数器辅助判别。

## 11-07 下午 手堵轮实验 → 积分死锁实锤
用户实验: 手堵一轮+轻推摇杆(他三轮转) → 回中(三轮正常停) → 松开手后受阻轮又多转一段。
机理推演(与代码逐行吻合):
1. 堵住+推杆: ref>0, rpm=0, err>0 → 积分充到 I_MAX=6A, 输出顶 7A 顶手。
2. 回中: 斜坡 250ms 内 ref 衰减到 0, rpm 仍 0 → **err 恒≥0, 积分只能充不能泄** →
   冻在 ~6A。他三轮 rpm>0 → err<0 → P 反刹+积分泄放 → 正常停。这就是不对称的根源。
3. 松手: a = KP×0 + 6A = 6A → 轮窜出去, rpm 升 → err<0 → 积分泄放 → 一段距离后停。
结论: "多转一段" = 积分死锁(11-05 诊断的③), 与"堵住回中仍顶电流"同源。
ST_STOP 状态机(回中即清积分+强制ref=0+纯P制动)是其正解, 用户尚未实施。
注意: 该机制不能解释"推杆时某轮突然完全无响应"——那仍指向电调侧(见上文硬件嫌疑)。

## 11-07 13:50 积分治理方案落地（5处改动，编译通过 text=31260）
Ozone 实测证据: s_wheel_i 深坑通道=s_wheel_i[2]→ID3(右后), 实测谷底 -5.2689A,
放电 τ≈1.3s(1s 冲到 -5.27, 约4.5s 泄完, 反推堵时 err≈-2600rpm)。
采用"轻量版"(不加状态机): 积分只做静差微调+松杆即清。
- rc_dbus.h: KP 0.002→0.004(松杆后 -KP*rpm 即纯制动), FF 0→0.0008(占位,需实测下调),
  I_MAX 6.0→1.5(积分只留微调余量)。KI 维持 0.002。
- rc_dbus.c(RC_WheelRef[i]=ref 后): `if (wheel_abs(ref) < 50.0f) s_wheel_i[i] = 0.0f;`
  → 松杆当拍积分归零, 死锁能量池消失。
- ★关键约束: I_MAX 与 FF 必须同改; FF=0.0008 满杆给 6.4A 明显偏大,
  落地需按"稳态电流÷稳态转速"实测标定(预计 0.0002~0.0004)。
- 已知代价: 静止无保持力矩(坡上溜, 本来也没有); 组合运动中某轮 ref 过 ±50rpm 窗口时
  积分被清(窗口小、P 主导, 影响可忽略)。
- 验证项: 架空重做堵转实验→s_wheel_i 应封在 ±1.5, 松手残余 <750rpm;
  落地直行看是否跑偏(若跑偏先调 FF 别动 I_MAX)。
- 未做(保留): 电调拨码/供电排查(满杆无响应仍指向电调侧); ST_STOP 状态机被此轻量版替代。

## 11-07 14:00 批判复审 → 轻量版被推翻重做（编译通过 text=31364）
第三方批判三条全部成立: ①|ref|<50 清积分晚 250ms(斜坡32rpm/拍); ②清完积分 PI 仍可能
出驱动力(ref=40,rpm=0→+0.19A); ③KP翻倍+FF=0.0008 与结构修复混在一起无法归因。
最终形态(现行代码):
- 回退 KP=0.002/FF=0(单变量原则), 保留 I_MAX=1.5(用户认可的"限制积分贡献"目标)。
- 删除 |ref|<50 清积分行。
- rc_dbus.c 失能/故障分支后新增 `else if (mix_state == 1u)` 分支: 当拍 Mecanum_Reset()
  +四轮积分/目标清零+跳过PI; 制动=wheel_clamp(-STOP_KP*rpm, ±STOP_A=3.5A),
  |rpm|<STOP_QUIET_RPM(50) 时电流撤 0。宏: RC_WHEEL_STOP_KP=0.002/STOP_A=3.5/
  STOP_QUIET_RPM=50(rc_dbus.h:48-50)。
- 已知代价: 静止无保持力矩(坡溜); I_MAX=1.5+FF=0 稳态转速误差=(摩擦A-1.5)/0.002 rpm,
  摩擦约3A时≈750rpm下垂, 待落地数据再调。
- 验收(离线可判): 回中当拍四轮 RC_WheelRef/s_wheel_i 归零; rpm=0 时 raw=0。
