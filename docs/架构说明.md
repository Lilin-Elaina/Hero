# Remote_Control 工程架构说明

> 更新：2026-11-19（分层重构后）
> 目标：`application → modules → bsp → HAL` 单向依赖；改功能只动上层，换芯片只动 bsp。

## 1. 三层职责

| 层 | 回答的问题 | 里面有什么 | 不允许 |
|---|---|---|---|
| `application/` | 机器人**要做什么** | 任务编排、模式选择、控制环、参数表、调试镜像 | 直接调 `HAL_*()`；被 modules/bsp include |
| `modules/` | **器件怎么驱动** | CAN 电机协议、DBUS 遥控协议、BMI088+姿态解算、麦轮混控 | include `application/`；直接调 `HAL_*()` |
| `bsp/` | **片上外设怎么用** | FDCAN、UART5+DMA、SPI2、时基 | include `modules/` 或 `application/` |

依赖方向只有向下一条：`application → modules → bsp → HAL`。

## 3. 一次控制拍发生了什么（1 kHz）

```
TIM/SysTick 1ms
  └─ RC_Control_Task()                       application/robot.c
       ├─ RC_IsOnline() / RC_Norm()          modules/remote/dbus.c
       ├─ 拨杆 → follow_on / spin_mode（40 ms 去抖）
       ├─ 使能三态机（WAIT → ARMING 100 ms → READY）
       ├─ CAN2 活性看门狗（20 ms 无帧 → 重启用）
       ├─ RC_Yaw_Step()                      application/gimbal/*.c
       │    └─ 跟随/手动：yaw 车体系角度环 + 世界稳向
       │       小陀螺：世界目标 → 关节目标 + 底盘转速前馈
       ├─ RC_Wheel_Step()                    application/chassis/chassis.c
       │    └─ Mecanum_Mix() → 四轮 PI → 电流
       └─ RC_Fric_Step()                     application/robot.c
```

## 4. 三条规则（`make check` 会自动查）

1. **不许反向依赖**：`modules/` 不能 include `application/`，`bsp/` 不能 include 上面两层。
2. **上层不许直接调 HAL**：`application/` 和 `modules/` 里 `HAL_*()` 出现次数必须为 0。
3. **bsp 不许知道业务**：CAN 收到什么帧、怎么解释，由注册进来的回调决定。

`make check` 输出两项：硬规则违规（必须 0，否则退出码 1）、软提示（APP 直接用 `bsp_time`/`bsp_can`，已接受，属于系统服务）。

## 5. 加新功能的落点

| 想做的事 | 改哪里 |
|---|---|
| 加一个新电机 | `modules/motor/` 新文件 + `bsp_can` 注册回调 |
| 改 PID / 限幅 / 阈值 | `application/rc_dbus.h`（只改参数，不碰逻辑） |
| 加一种工作模式 | `application/robot.c` 的模式选择 + 一个新 `*_Step()` |
| 换主控芯片 | 只改 `bsp/`（HAL 调用全在这里） |

## 6. 已知欠账

- `robot.c` 里 `RC_Control_Task()` 仍有 300 行（模式选择 + 看门狗 + 编排混在一起），可继续拆 `RC_Mode_Step()`。
- `ins.c` 里 BMI088 驱动与姿态解算还在同一文件，可按参考工程拆成 `bmi088.c` + `ins.c`。
- 三处 `HAL_*` 仍在 `bsp/` 之外？没有——已清零，可用 `make check` 复核。
- `bsp_init` 汇总入口未做（现在仍由 `main.c` 逐个调用 `FDCAN*_Start` 等）。
